# 上下文压缩折叠块

- 状态：生效中（2026-11-21 建立）

## 目标

会话里「上下文已压缩」这条折叠记录（宿主 MessageItem 的 CompactionItem）在皮肤下两态都可读：折叠行与展开后的压缩摘要正文都不与底色糊在一起，摘要正文里的行内 code 尤其要认得出。

## 约束

- 结构（宿主 app.asar 内 MessageItem 组件）：`div.LOmM4q_compactionRow > button.LOmM4q_compactionButton（compactionTitle + compactionSep + compactionSummary）+ div.LOmM4q_compactionBody > MarkdownText`。展开体只在 `node.summary !== null` 时渲染。
- 折叠行文字取 `--dsw-alias-label-tertiary`，皮肤该档是灰褐 `#9e9780`，落合成底 `#080a06` 实测 **6.81:1**（标题、分隔点、摘要同值），达标，本轮不改。
- 展开正文里的行内 code 走宿主全局 `.markdown :not(pre) > code`：它只设近白底 `--dsw-alias-markdown-inline-code`（浅色主题 `#fafafa`，实测 `rgb(250,250,250)`）**不设字色**，字色继承皮肤全局奶油 `label-primary #f4ead6` —— 实测 **1.14:1**，整串胶囊等于白底白字。属设计风格第八条「宿主已是浅底、皮肤压的浅字」方向一。
- 修法与对话区、思考块、插件正文几处行内 code 同一视觉语言：**宣纸底 + 墨字 + 铜边**（`--vj-paper` / `#1c1a14` / `rgba(196,163,90,.45)`），深浅两态一致，因为深色主题下 `--vj-paper` 同样是宣纸色。
- 锚点：宿主手写的固定类名 `compactionBody` / `compactionRow`（C 级，CSS Module localName，不参与构建 hash），外面套 `body[data-dsh-815]`（B 级）收窄。必须用 `[class*='compactionBody']` 属性选择器——本文件是 CSS Module，裸写 `.compactionBody` 会被编译成 `哈希_compactionBody`，与 DOM 对不上。
- 正文其余元素（标题、列表、普通段落）继承 `label-tertiary`，落深底已达 6.81:1，不动；不改组件源码、不改节点结构、不加装饰。

## 涉及文件

- `src/client/vj815.module.css`（紧跟「对话区行内 code」段之后）

## 验收

- `body[data-dsh-815] :is([class*='compactionBody'], [class*='compactionRow']) [class*='markdown'] :not(pre) > code` 命中 > 0；真实压缩记录（会话「浏览器动画CPU占用排查与修复」）展开后实测正文 195 处行内 code 全部命中。
- 行内 code 对胶囊底 ≥ 4.5:1：实测 **14.52:1**（修前 1.14:1），字色 `rgb(28,26,20)` / 底 `rgb(243,234,212)`。
- 压缩正文内逐叶子元素扫描文字对合成底 < 4.5:1 的元素数为 0（实测 236 个叶子、0 处；修前为全部行内 code）。
- 折叠行（未展开）对比度 6.81:1，展开与折叠两态亮度一致。
- 浅色与深色两态都必须验；`pnpm test` 只覆盖 JS 侧 DOM 行为，不能替代样式实测。

## 已知边界

- 压缩摘要的 Markdown 若含围栏代码块，块本身走 `--dsw-alias-markdown-code-block`（皮肤已接管为深底），不在本条范围内。
- 折叠行摘要串是宿主的 `message.compaction.completed` 文案（`已压缩 {items} 条历史记录（约 {tokens} tokens）`），皮肤不翻译、不改措辞。
