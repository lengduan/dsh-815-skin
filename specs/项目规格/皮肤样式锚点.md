# 皮肤样式锚点

- 状态：生效中（2026-11-05 建立）
- 适用范围：`src/client/vj815.module.css` 的全部选择器、`src/client/index.ts` 与 `src/client/titlebar-brand.ts` 里的 DOM 查询，以及后续新增的一切样式与装饰代码。

## 规则

皮肤只把样式挂在**跨 DSH 构建不变**的锚点上；节点上由构建期生成、每次构建都可能变的 hash 标识（CSS Module 哈希前缀、打包 hash、scoped 属性等）一律不作锚点。

CSS Module 的类名形如 `哈希_localName`（`BfLV8a_bubble`、`N9Zj0W_add`）：`localName` 由宿主源码写定，`哈希` 每次构建重算。皮肤依赖的是前者与宿主手写的语义属性，不是后者。

## 失效史

2026-09-24 的 diff 视图修复把六条选择器挂在 `FileDiff.module.css` 的 hash 前缀 `DoHURa_` 上；DSH 升到 `0.2.0-rc.1-7bb30cd` 后同一模块前缀变成 `N9Zj0W_`，六条在本机逐条实测命中 0 个，修复整体失效、用户重新报障。这是本规格的来由。现有约定写在 `src/client/vj815.module.css` 的「[匹配策略：只用固定类名，禁止哈希整串]」段（2026-11-05 读取时位于 :1400-1413）。

## 锚点分级

| 级别 | 锚点 | 现用例 | 约束 |
|---|---|---|---|
| A（首选） | 宿主手写的语义属性：`data-*`、`role`、`aria-*`、`data-testid`、`data-slot` | `[data-pane='sidebar']`、`[data-chat-flow-kind='assistant-step']`、`[data-tool='schedule_create']`、`[data-variant='think']`、`[data-diff-line='add']`、`[role='treeitem']`、`[aria-selected='true']` | 属性值取自宿主组件源码，不参与构建 hash |
| B | 插件自己写入的标识 | `body[data-dsh-815]`、`[data-skin-owner='815']`、`[data-vj-session]` | 由 `ctx.effect` 销毁器逐项撤回，不得残留 |
| C | 固定 id、宿主手写稳定类名 | `#root`；`sm-footer`、`ltp-btn` 一类手写名 | 新用前在本机 DOM 里确认该类名不带 `哈希_` 前缀。**本文件是 CSS Module：在 `vj815.module.css` 里裸写 `.lc-xxx` 会被编译成 `哈希_lc-xxx`，与插件 DOM 上的裸类名对不上（2026-11-05 实测 `.N_pGfa_lc-gran-btn` 命中 0）。引用插件手写类名必须写成属性选择器 `[class*='lc-xxx']`（仍属 C 级），或 `:global(.lc-xxx)`；不要写裸类名。** |
| D | CSS Module localName 后缀子串 | `[class*='_add']`、`[class*='bubble']`、`[class*='markdown']`、`[class*='sidebarCol']` | 必须叠一个 A/C 级容器收窄范围；近邻同名后缀用 `:not([class*='_added'])` 一类挡开；关键样式再并列一个 A 级锚点兜底 |
| E | 结构关系：`>`、`:has()`、`first-of-type`、`:is()` 组合、父子/兄弟位置 | `[class*='titlebar'] > [class*='button']:first-of-type` | 只作辅助收敛，不单独承载关键样式；宿主多插一层 wrapper 即失效 |
| 禁止 | 构建期 hash 标识 | `[class*='N9Zj0W_add']`、`[class*='DoHURa_add']`、`.fO69Vq_facts`、把 DSH 版本号或构建号写进选择器 | 命中不稳定，正是失效史的成因 |

## 写法要求

1. 主题 token（`--dsw-*`）能覆盖的样式，优先改 token 而不是加选择器 —— token 名比 DOM 结构更稳。
2. 只用到 D/E 级锚点的规则，必须再挂一个 A 或 C 级容器锚点限定范围。
3. 每条新规则旁写中文注释：用了什么锚点、为什么它稳定；若同时存在更高级别的候选锚点，说明为何没用它（沿用本文件现有注释习惯）。
4. JS 侧查询同样按上表；不得为命中节点在代码里固化 hash 类名。

## 验证清单（改完样式逐条过）

1. 静态：

   ```sh
   rg -n "class\*='[A-Za-z0-9]{4,}_" src/client | rg -v '^\S+:\d+:\s*(/\*|\*)'
   ```

   排除注释行后应 0 命中（`哈希_local` 形态；以 `_` 开头的 localName 后缀选择器不匹配此式）。`vj815.module.css` 的「[匹配策略]」段里作为反例保留的哈希串属文档说明，不算违规。
2. 复核：

   ```sh
   rg -n "class\*='[A-Za-z0-9]" src/client/vj815.module.css
   ```

   逐个确认值是 A~D 级手写名，不是 `哈希_local`。
3. 运行时：本机 DSH GUI 的 DevTools 里对每个新/改选择器执行 `document.querySelectorAll('<选择器>').length`，必须 > 0；目标元素、浅色与深色方案、折叠与展开态逐项目视。
4. 回归：`pnpm test` 只覆盖 JS 侧 DOM 行为，不能证明 CSS 命中，不得替代第 3 条。

## 变更流程

1. 接到需求，先读本文件与 `specs/功能规格/` 下对应文件。
2. 按锚点分级选锚点、改样式。
3. 过验证清单，把命中数与对比度结论写进注释或在交付说明里给出。
4. 宿主没提供任何稳定锚点、必须越过本规格时：先在本文件补一条写明场景与替代方案的豁免，再动代码；不在选择器里静默使用 hash。
5. 发现既有规则命中 0：定位失效的哈希前缀，按本规格改写锚点并回补失效史。
